# Инструменты: что есть, что даёт, чего нет

Всё ниже проверено запуском в этом окружении, а не взято из документации.

## Установлено

| Инструмент | Версия | Зачем |
|---|---|---|
| ffmpeg | 6.1.1 | декод, кодирование, фильтры, звук |
| Chromium + Playwright | 1194 | отрисовка графики холста |
| Pillow | 11 | покадровая компоновка, наезды |
| numpy | 2.4.6 | анализ звука, быстрая работа с кадрами |
| OpenCV | 4.14 | поиск лица, анализ движения |
| PySceneDetect | 0.7.1 | поиск склеек в длинном исходнике |
| tesseract + rus | 5.3.4 | чтение текста, вжатого в кадр |

**OpenCV нужен именно 4.x.** В версии 5 каскады Хаара вынесли из пакета, а
скачать их неоткуда — сетевая политика закрывает почти все CDN. В 4.14 все 19
каскадов лежат внутри колеса и работают без единого запроса в сеть.

## Фильтры ffmpeg, которые есть и пригодятся

`vidstabdetect` / `vidstabtransform` — стабилизация съёмки с рук в два прохода.
`loudnorm` — приведение громкости к EBU R128, платформы этого ждут.
`lut3d` — единый цветокор по LUT-файлу, чтобы выпуски выглядели одинаково.
`xfade`, `minterpolate`, `unsharp`, `deshake` — тоже на месте.
Кодеки: x264, x265, VP9.

## Замеры на реальном материале

Проверялось на 16-секундном ролике 720×1280, 30 fps.

**Поиск лица.** Каскад Хаара находит лицо на 95 % кадров, 0.09 с на кадр.
Достаточно считать каждый третий кадр и сглаживать между ними — минута видео
разбирается примерно за полминуты. Центр лица гулял в пределах
`x = 262..380`, `y = 417..500`: то есть при наезде рамку действительно надо
вести за лицом, а не держать неподвижной.

**Поиск пауз.** Порог считается от фонового шума (15-й процентиль + 8 dB).
На 16 секундах нашлось 6 пауз общей длиной 2.6 с — шестая часть хронометража.
На получасовом интервью это и есть главный рычаг: без вычистки пауз минутный
ролик из него не собрать.

## Чего нет и не будет

**Распознавание речи.** Whisper недоступен: huggingface.co и CDN OpenAI
закрыты сетевой политикой. Поэтому субтитры приходят готовыми. По той же
причине нет принудительного выравнивания текста по звуку и авто-перевода.

**PyTorch** со своего индекса не ставится (`download.pytorch.org` закрыт), но
колёса есть на PyPI, а он открыт. То есть поставить можно — ценой гигабайтов и
медленного счёта без GPU.

**Веса моделей с GitHub Releases скачиваются** — проверено на `yolo11n.pt`.
Значит детекция объектов (в том числе собак) для разборов языка тела возможна.
Но она тянет за собой PyTorch, а инференс без GPU медленный. Браться за это
стоит только под конкретную задачу.

## Что решили не подключать

`moviepy` — повторяет то, что уже собрано, и режет точность: наезды считает
через ffmpeg, а тот двигает рамку целыми пикселями и дёргается.
`ffmpeg-python` — обёртка ради обёртки, `subprocess` тут читается лучше.
`pysrt` / `webvtt-py` — свой разбор уже умеет то, чего они не умеют: чинить
срезанные ведущие нули в миллисекундах, как их пишет VEED.
